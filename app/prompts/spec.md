# 整理规范

你要把 OneNote 导出的 PDF 文字层，整理成 markmap 思维导图能渲染的 Markdown 笔记。
产物只有标题和列表：markmap 只渲染标题和列表，其他一律不写。

## 结构（通用）

1. 顶部一行 `# <标题>`：整套笔记的整体主题
2. `##`：知识板块（如「并发编程」「MySQL」「设计模式」）。**同一板块内多页内容合并，不要按页分段**
3. `###`：板块内子主题；板块很平就跳过，直接挂列表
4. `- `：具体要点。子要点 2 空格递增，**只用偶数空格**
5. 不写表格、不写代码块、不写链接

## 内容（通用）

1. 保留全部技术名词、英文标识符、API 名、例子。不翻译、不缩写、不改大小写
2. 不改代码关键字大小写，不给变量取新名字
3. **只删这些**：跨页硬换行造成的句子碎片（接回去）、重复粘贴的同一句副本、连续 3+ 空行、页脚页码、时间戳
4. 不做 OCR 修订，不补原文没有的示例代码，不加原文没有的心得
5. 原文里的日期（`5.20`）是学习场次标记，属于元数据，去掉

## 缺口处理

1. 只有页码没有文字的页（整页截图）：先看**前后页**在讲什么，上下文能推出就推断补上；推不出来不要编
2. 原文里有「下面这个」「如下所示」这类指代图片的引导句、而图片没文字记录：**删掉这句**，别留半截话
3. 结尾加 `## 待补充`，列出：只有标题没正文的小节、没能转写的纯截图页、原文明确说「以后再补」的内容。
   若有没有，Ⓐ 全无缺口时也要写一行「（无缺口）」占位，Ⓑ 有缺口时逐条列页码与推断结论

## 已知边界

- 纯截图页转不了文字，只能靠上下文推断，或留缺口
- 图片全丢。代码截图不进 md——导图要的是骨架，不是代码仓库
